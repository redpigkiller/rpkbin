# 目標描述參考

一個目標由一個 Python 檔描述。檔案必須提供 `TARGET`（`Target`），也可以提供 `SIM`（`SimBinding`）和 `STUBS`（外部函式的測試機器碼）。產生組語需要 `TARGET`。要用模擬器檢查指令或程式，再提供編碼函式與模擬器綁定。

宣告用的類別都從 `rpkbin.mcucc.target` 匯入。`load_target(path)` 回傳 `Target`。`load_target_file(path)` 回傳 `(target, sim, stubs)`，兩個選填項目未提供時各為 `None`。載入器會執行目標檔的 Python 程式碼，請只載入可信任的檔案。

## 撰寫一個新目標

1. 從[完整範例](../examples/README.md)走一次 `lint-target → check-forms → compile → verify`，確認看得到組語、指令檢查結果及程式差異測試結果。範例附有可直接載入的[目標描述檔](../examples/target.py.txt)。
2. 宣告硬體確實具有的資料空間、程式空間、暫存器、別名與旗標。按指令可接受的位置建立暫存器類別，再定義參數與回傳值的位置。
3. 先加入 `jmp` 和 `ret`，再補上代表性來源程式所需的 form。一條機器指令有不同的運算元或編碼時，為每種形式各寫一個 form。用 `lint-target` 檢查宣告與各寬度的可用性，接著編譯一支小函式查看組語。
4. 為 form 補上 `encode`，並接上獨立建模的模擬器。用 `check-forms` 核對每條指令的長度、結果、旗標與副作用。通過後用 `verify` 比較整支函式的執行結果，並把使用到的外部函式、資料空間與呼叫慣例納入測試。

[README](../README.md) 列出各命令的參數、回傳結果與 Python API。

## 目標、空間與儲存單位

`Target(name, cell_bits, spaces, regs, aliases, classes, flags, forms, abi, long_branch, comment, local_label, label_def)` 的欄位皆必填。

| 欄位 | 填法 |
| --- | --- |
| `name` | 非空字串，供顯示用。 |
| `cell_bits` | 目前必須為 `8`。一個 cell 是一個位元組，程式和資料位址都以 cell 計。 |
| `spaces` | `Space` 的 tuple，恰好一個程式空間，至少一個資料空間。 |
| `regs`、`aliases`、`classes`、`flags`、`forms` | 各類宣告的 tuple。基本暫存器和 form 的宣告順序會影響候選成本相同時的選擇。 |
| `abi` | `Abi` 物件。 |
| `long_branch` | `"none"` 或 `"invert_over_jump"`，見下方分支說明。 |
| `comment` | 組語註解行的非空前綴，例如 `";"`。 |
| `local_label` | 區域標籤格式，例如 `".L{fn}_{n}"`。恰好各含一次 `{fn}`（函式名）和 `{n}`（序號）。產生的名稱須符合 `[A-Za-z_.][A-Za-z0-9_.]*`。 |
| `label_def` | 函式入口與區域標籤的定義行格式，例如 `"{name}:"`。恰好含一次 `{name}`。 |

| 建構子 | 意義 |
| --- | --- |
| `Space(name, addr_bits, kind)` | `kind` 是 `"data"` 或 `"program"`。`addr_bits` 至少為 1，位址範圍為 `0 <= addr < 2**addr_bits`。 |
| `Reg(name, bits)` | 獨立的基本儲存單位，`bits` 必須等於 `cell_bits`。 |
| `Alias(name, parts)` | 由高位到低位列出至少兩個名稱的 tuple。部分可再引用別名，遞迴展開後的基本暫存器不能重複或形成循環。別名寬度是各部分的寬度總和。 |
| `Cls(name, members)` | 非空 tuple，列出同寬的基本暫存器或別名。一個位置可以屬於多個類別，類別也可以只有一個固定成員。 |
| `Flag(name)` | 一個值為 0 或 1 的旗標。沒有旗標時用空 tuple，這樣的目標無法提供 `br`。 |

上述名稱符合 `[A-Za-z_][A-Za-z0-9_]*`，並共用同一個命名空間。以 `Alias("pair", ("b", "a"))` 為例，`a` 與 `b` 是兩個 8 位元暫存器。`pair` 的高位元組是 `b`，低位元組是 `a`。寫入其中一個部分會立即改變 `pair` 的對應位元。兩個位置只要共用任一基本單位就算重疊，因此 `pair` 與 `a` 重疊。

## Form 與標準運算

`Form(id, op, width, operands, bind, bytes, asm, flags_read=None, flags_write=None, clobbers=(), encode=None)` 描述一種可選用的指令形式。

| 欄位 | 填法 |
| --- | --- |
| `id` | 在目標內唯一的非空字串，出錯時用來找出對應 form。 |
| `op`、`width` | 使用下表的標準運算名稱。資料運算的寬度為 8 或 16，控制轉移與返回為 0。 |
| `operands` | 運算元宣告的 tuple，各自有唯一的識別字名稱。 |
| `bind` | 將標準引數名稱對到宣告的運算元名稱，剛好覆蓋該運算所需的鍵。例如 `{"dst": "d", "a": "d", "b": "s"}` 表示同一個 `d` 是目的與第一個來源。來源須按指令開始時的值解讀，包含合法的重疊組合。 |
| `bytes` | 此 form 佔用的程式 cell 數，至少 1。 |
| `asm` | 一行組語模板，使用 `{運算元名稱}` 替換，`{{`、`}}` 產生字面大括號。輸出時自動加四個空格。 |
| `flags_read`、`flags_write` | 讀取的條件與寫入的語意，見下方旗標表。省略時為空。 |
| `clobbers` | 目的運算元以外可能被改寫的基本暫存器或別名，使用名稱的 tuple。 |
| `encode` | 選填的機器碼編碼函式，見下方說明。 |

表中 `a`、`b` 指標準引數名稱。資料寬度為 `w` 時，運算結果保留低 `w` 位元。設計 `ld` 和 `st` 時，以一個資料 cell 的讀寫來描述。

| `op` | `bind` 鍵 | 語意 |
| --- | --- | --- |
| `mov`、`const` | `dst`、`a` | 複製 `a` 到 `dst`。`mov` 從暫存器取值，`const` 的 `a` 是立即值。 |
| `add`、`sub`、`and`、`or`、`xor` | `dst`、`a`、`b` | 加、減與位元運算，`sub` 計算 `a - b`。 |
| `not`、`neg` | `dst`、`a` | 位元反相、取負值。 |
| `shl`、`shr` | `dst`、`a`、`b` | 邏輯左移、右移，`b` 是立即值。用 `values` 列出實際支援的移位量，例如 `(1,)`。 |
| `cmp` | `a`、`b` | 以 `a - b` 為比較依據，結果用旗標表示，沒有 `dst`。 |
| `ld`、`ld_ind` | `dst`、`a` | 讀取 `a` 指定的資料 cell。分別用 `M`（直接位址）與 `P`（位址暫存器）表示 `a`。 |
| `st`、`st_ind` | `a`、`b` | 把 `b` 寫入 `a` 指定的資料 cell。`a` 分別使用 `M` 與 `P`。 |
| `jmp`、`br`、`call` | 空字典 | 各自有一個 `T` 運算元，分別表示無條件跳躍、條件分支和呼叫。 |
| `ret` | 空字典 | 返回呼叫者。 |
| `push`、`pop` | 分別為 `a`、`dst` | 將暫存器的值推入堆疊，或從堆疊取值到暫存器。以相同的暫存器類別和寬度成對宣告。 |

目的位置 `dst` 用 `R` 宣告。編譯器根據 `mov`、`const`、`ld`、`st` form 判斷能否跨位置搬移。算術 form 可用 `M` 為值運算元，以便直接讀取記憶體。拆分與組合值使用別名的部分與搬移，例如取 16 位元值的高位元組。遇到目前程式必須使用、目標卻缺少相應 form 或搬移路徑的情況，編譯會回報 `UnsupportedError`。

### 運算元與組語模板

| 建構子 | 值域與渲染 |
| --- | --- |
| `R(name, cls)` | `cls` 為同寬的暫存器類別。字面輸出暫存器或別名的名稱，包含只有一個成員的類別。 |
| `I(name, bits, signed=False, values=None)` | 立即值。`bits` 為正整數且不超過 form 寬度，目前須用 `signed=False`。`values=None` 允許整個無號值域，或用非空 tuple 列出合法值。較窄的立即值須具有零擴展的語意。小於 10 時輸出十進位，其他值輸出小寫十六進位（含 `0x`，無補零）。若需要 `#` 等前綴，寫在模板中。 |
| `M(name, space, bits=None)` | 在指令中直接指定的資料位址。`bits` 預設取該資料空間的 `addr_bits`，也可給較短的正整數欄位寬度。位址必須小於 `2**bits`。渲染為帶 `0x` 的小寫十六進位，依有效欄位寬度每 4 位元取一個字元、向上取整補零。 |
| `P(name, cls, space)` | 保存資料位址的暫存器，類別寬度必須等於資料空間的 `addr_bits`。輸出暫存器名。`Ptr` 型別支援的指標寬度為 8 或 16。 |
| `T(name, rel_bits=None, abs_bits=None, base="end")` | 跳躍或呼叫的目標。恰好指定一個正整數位寬。組語輸出為標籤名稱。 |

`R`、`I`、`M`、`P`、`T` 運算元都要用具名占位符。只有 `I.values` 恰有一個值時，可以省略該立即值的占位符。舉例來說，模板 `"step_left {d}"` 可以搭配 `I("count", 1, values=(1,))`，並在 `bind` 以 `"b": "count"` 宣告移一位。

`encode(values)` 以運算元**宣告名稱**為鍵，收取下列值，回傳恰好 `bytes` 個整數 cell 的 tuple。每個 cell 須在 `0 <= cell < 2**cell_bits` 範圍內。請寫成純函式，同一組值應得到同一組編碼。

| 運算元 | 傳入 `encode` 的值 |
| --- | --- |
| `R`、`P` | 暫存器或別名名稱字串。 |
| `I`、`M` | 立即值或資料位址的整數。 |
| `T` | 已解析的有號相對偏移或無號絕對位址，型別為整數。 |

例如 `bind={"dst": "d", "a": "k"}` 的立即值載入，若選到暫存器 `a` 與常數 10，`encode` 會取得 `{"d": "a", "k": 10}`。模板 `"put {d}, #{k}"` 則渲染成 `put a, #0xa`。編譯成組語可省略 `encode`。組譯與 `verify` 要求實際選用的 form 能編碼。有 `SIM` 時，`check-forms` 對任何缺少 `encode` 的 form 列出失敗。若 encoder 的回傳長度與宣告的 `bytes` 不符，組譯、編譯與差異驗證都回報 `TargetError`，附 form id 與期望、實際長度；`check-forms` 會列為失敗項。

### 跳躍範圍與長分支

- `rel_bits=n` 的有號偏移範圍是 `-2**(n-1)` 到 `2**(n-1)-1`，單位為 cell。偏移是目標位址減去基準。以位址 10 上長度 2 的指令跳到位址 7 為例，`base="end"` 的偏移為 −5，`base="start"` 為 −3。
- `abs_bits=n` 傳入的值是目標絕對位址，範圍為 `0 <= addr < 2**n`。目標也必須放得進程式空間。請特別核對實際載入位址。
- `jmp` 和 `ret` 各至少一個 form。程式有呼叫時需要 `call`，而 `verify` 的測試驅動一律需要可編碼的絕對 `call`，即使來源程式是一支沒有呼叫的函式。
- 編譯器可從較短的 `jmp` 或 `br` 切換到可達的候選。`long_branch="none"` 停用反轉條件再跳躍的合成。同一條件的所有已宣告 form 都可供選擇，編譯器取可達者。全部不可達時回報 `exceeds all declared ranges`。`"invert_over_jump"` 允許以反向條件跳過一條絕對 `jmp`。每個分支條件都要提供讀同一旗標相反值的 form，並有絕對 `jmp`。請確認反向分支的範圍足以跨過該 `jmp`。所有可選跳法都不適用時，編譯會回報 `UnsupportedError`。

### 旗標語意與條件

`flags_read` 僅供 `br` 使用，恰好有一個項目，例如 `{"z": 1}` 表示 `z` 為 1 時跳躍。`flags_write` 用旗標名稱對應下列語意詞。空字典表示旗標中立。從比較到分支之間，新增的搬移指令須保留旗標。

| 語意詞 | 值為 1 的條件或意義 |
| --- | --- |
| `zero` | 寬度截斷後的結果為 0。`cmp` 以差值為結果，`mov`、`const` 與載入則以寫入目的位置的值為結果。 |
| `carry` | `add` 的無號和超出 form 位寬。 |
| `borrow`、`nborrow` | 分別為無號 `a < b` 與 `a >= b`，用於 `sub`、`cmp`。 |
| `borrow_msb0`、`nborrow_msb0` | 同上一列，只承諾兩個運算元的最高位元同為 0 時成立。其他輸入下可為任意值。只用於 `sub`、`cmp`。 |
| `shift_out` | `shl`、`shr` 移出的最後一個位元。使用此語意時，移位量需在 1 到 form 寬度之間。 |
| `undef` | 旗標可能被破壞，編譯器不能使用它的值。 |

若某旗標可能改變，但指令在宣告的合法輸入上沒有符合上表的值，請寫 `undef`。旗標只有在硬體確定保留原值時才從 `flags_write` 省略。例如載入資料可能改寫零旗標，即使程式平常不用它，也須據實宣告。存放、堆疊與跳轉等操作若會修改旗標，可用 `undef` 集中描述其副作用。

編譯器把 `cmp` 宣告寫入的旗標與 `br` 宣告讀取的旗標配對。`zero` 的 1、0 分別是等於、不等於。`borrow` 的 1、0 分別是無號小於、大於等於。`nborrow` 則相反。交換比較的兩個來源或反轉分支可補出其他關係。含 `_msb0` 的配對只有在編譯器能證明兩個最高位均為 0 時才會使用，像是某些先將較窄值零擴展的比較。請選對適用範圍的語意詞。`carry` 和 `shift_out` 不參與比較配對。

對 `ld`、`st`，綁到 `a` 的位址運算元須是 `M`。對 `ld_ind`、`st_ind`，該運算元須是 `P`。若種類不符，載入 Target 即得到 `TargetError`，訊息包含 form id 與期望種類。

## ABI 與 spill pool

`Abi(arg_locs, ret_locs, callee_saved)` 是函式呼叫的預設約定。

| 欄位 | 填法 |
| --- | --- |
| `arg_locs` | 寬度（8 或 16）到候選位置 tuple 的字典。依參數順序，每個參數選同寬候選中第一個未與已選位置重疊者。 |
| `ret_locs` | 寬度到單一回傳位置的字典。`Ptr` 和整數都按自身寬度選位置。 |
| `callee_saved` | 預設由被呼叫者保留的暫存器與別名名稱 tuple。`@fn(preserves=...)` 可針對個別函式覆寫。保留位置不得與回傳位置重疊。 |

位置可以是基本暫存器或別名的名稱，也可以是 `MemLoc(space, addr, n=1)`。後者表示資料空間中從 `addr` 起的 `n` 個連續 cell，全部必須在範圍內。函式的記憶體參數與回傳值目前都只支援單 cell。16 位元的 ABI 資料請使用兩部分的別名，例如 `"pair"`。Target 載入會檢查欄位與位址範圍，容許宣告合乎結構的多 cell 位置。編譯選到該位置作為參數或回傳時會回報 `UnsupportedError`。兩個記憶體位置在同一空間且位址範圍有交集才算重疊。

例如 `Abi({8: ("a", "b", MemLoc("data", 0x20)), 16: ("pair",)}, {8: "a", 16: "pair"}, ())` 會將先出現的 16 位元參數放在 `pair`，下一個 8 位元參數便須跳過 `a`、`b`，取 `data[0x20]`。呼叫指令的 `clobbers`、被呼叫函式可能改寫的位置、參數與回傳位置，都會影響呼叫端的值保存。編譯器保守採用所有 `call` form 的 `clobbers` 聯集，呼叫後原有旗標一律視為未定義。個別函式的覆寫方式見[語言參考](language.md)。

`spill_pool` 是編譯設定，例如 `CompileConfig({"data": (0x40, 0x5f)}, comments=True)`。`(lo, hi)` 包含兩端，至多配置一個資料空間。`{}` 表示不提供槽。範圍必須合法，且不能與目標預設或函式指定的 ABI 記憶體位置重疊。呼叫者要確保這段空間可由編譯出的程式專用。能否把某個值放入這裡再取回，取決於相容的直接 `st`、`ld` form 與實際位址值域。內部的兩個 cell 私有槽依低位元組在低位址的順序存放。[驗證保證與使用條件](guarantees.md)

## 模擬器綁定與外部函式

`SimBinding(make_sim, program_space, pc, halt_cells, names=None, init=None)` 提供驗證用的 isasim 模擬器。與編譯器的 form 宣告分別建立指令模型，可以讓兩邊的語意或編碼差異由檢查顯現。

| 欄位 | 填法 |
| --- | --- |
| `make_sim` | 無參數的 callable，每次回傳一個全新的 isasim `Simulator`。 |
| `program_space` | 模擬器中的程式空間名稱。 |
| `pc` | 模擬器上可讀寫的程式計數器名稱。上面兩個欄位直接使用模擬器名稱。 |
| `halt_cells` | 讓模擬器停止的一條指令的機器碼 cell tuple，供測試驅動使用。 |
| `names` | 目標名稱到模擬器存取名稱的字典。未列出的名稱直接沿用。可將別名映到模擬器的寬暫存器，再用模擬器欄位對應各部分，例如 `{"pair": "word", "a": "word.lo", "b": "word.hi"}`。資料空間只填空間名稱，例如 `{"data": "memory"}`。 |
| `init` | 選填 callable，接收模擬器，於建立後、載入程式前呼叫。可初始化編譯器看不到的堆疊狀態。測試之後會另行設定可見暫存器和測試資料。 |

`STUBS` 是外部函式名稱到機器碼 cell tuple 的字典，例如鍵 `"helper"` 對應宣告為 `@extern(...)` 的 `helper`。差異測試把替身放在編譯函式之後，依名稱解析呼叫。替身須能放在任意位址、沒有內部跳躍、以目標的返回指令結尾，並遵守該外部函式宣告的 ABI 與副作用。要測到呼叫該函式的路徑，須提供對應替身並讓機器碼行為與參考執行一致。[差異測試怎麼比較結果](guarantees.md)

## 如何讀 `lint-target` 與 `check-forms`

`lint-target` 載入並驗證目標宣告，再按 `op`、`width` 列出是否有 form（`available`）、數量（`forms`）和最小位元組數（`min_bytes`）。一列 `available=False` 可代表目標省略的功能。從最小的來源函式逐步加上呼叫、運算與記憶體存取，可以確認各路徑是否都有適用的 form。收到載入診斷時，先依訊息中的欄位或載入位置檢查宣告。指令的真實效果要靠下列模擬測試比對。

`check-forms` 使用新的模擬器反覆執行每個 form。預設從種子 0 取樣，`--seeds N` 使用從 0 開始的 `N` 個種子。運算元取邊界、單一位元、其補數和固定種子的隨機值，涵蓋合法的立即值、位址與跳躍欄位，以找出編碼漏位或對調。每個 form 的一般取樣至少 12 組，也會安排可行的暫存器重疊與彼此獨立的組合。每次建立模擬器都會初始化整個宣告的資料空間，空間大小會影響測試成本。

| 檢查 | 失敗時先檢查什麼 |
| --- | --- |
| 指令長度 | 非跳躍單步執行後，程式計數器的增量須等於 `bytes`。核對解碼後的實際長度，執行週期另外計算。 |
| 運算結果 | 目的暫存器或別名須等於標準運算的結果。若只在重疊時失敗，檢查是否在取完來源前就寫了目的位置。若只在各來源獨立時失敗，核對運算元綁定以及編碼有沒有把兩個來源寫成同一個。 |
| 副作用 | 檢查可見暫存器單位、旗標和資料 cell。只有目的位置、`clobbers`、`flags_write` 及 store 指定的 cell 可改變。模擬器內部的堆疊指標及儲存不在此比較。 |
| 旗標值 | 對具有已知數值結果的 form，比對宣告的旗標語意，包含搬移、常數、載入與比較。`undef` 允許任何值。帶 `_msb0` 的語意額外取樣兩來源最高位同為 0 的情況，只在該範圍內核對這個旗標。 |
| 記憶體 | 直接或間接載入的結果須等於指定 cell。存放須寫入正確的值，其他 cell 的變動會由副作用檢查指出。 |
| 分支 | `jmp` 後須到宣告目的地。`br` 測旗標滿足與不滿足兩種情況，分別核對目的地與下一條指令的位址。相對分支包含最小、最大與零偏移。 |
| 比較與分支配對 | 先執行 `cmp` 再執行相容的 `br`，確認實際跳躍與宣告推導出的比較條件一致。測試會依該 form 的目標值域安排可達目的地。 |
| 堆疊 | `push` 後由測試驅動改寫來源，再用 `pop` 取回原值。目的可與來源相同、重疊或分開。兩條指令各自都要符合它們宣告的副作用。 |
| 呼叫與返回 | 對每個取樣目的地，先步進 `call` 並核對到達位址，再放入 `ret` 以檢查能否返回呼叫的下一條指令。分階段載入也能測到目的地與測試驅動重疊的情況。分別比較兩條指令的副作用。 |
| 編碼長度與值域 | 核對編碼器回傳 tuple、cell 數等於 `bytes`、每個 cell 在合法範圍內，包含目標欄位的邊界值。 |

輸出 `c9 skipped: out_of_space=N ret_not_fit=M` 記錄呼叫測試的略過數。`out_of_space` 表示目的地超出模擬器程式空間，該次呼叫未執行。`ret_not_fit` 表示仍檢查呼叫抵達位址，但該位址放不下完整返回指令，因此略過返回步驟。略過計數本身不會使檢查失敗。一致性不符時結束碼為 1。缺少 `SIM` 時命令會印出 `unverified: no SIM` 並以 0 結束，表示未執行模擬檢查。

有失敗時先依 form 名稱核對宣告、編碼與模擬器。即使取樣通過，仍須以代表性程式執行 `verify`，才能檢查多條指令合用、ABI 與資料存取的行為。[錯誤目錄](errors.md)
